# 电销CRM 部署教程

---

## 一、镜像有哪几个？该用哪一个？

### 直接给结论

> **只拉 1 个：`jiankujidu/telecrm-allinone:1.0.0`**
>
> 它是「一体化镜像」—— 管理后台页面和后端接口**打包进同一个容器**，只占 **8080 一个端口**。
> 本教程默认就是用它，部署包里的 `docker-compose.yml` 也只拉这 1 个（外加官方 MySQL）。

为什么之前有 4 个、现在又有第 5 个？因为**技术栈有两套（PHP / Java）、角色有两种（后端 / 后台）**，交叉就有 4 个：

| 镜像名 | 技术栈 | 角色 | 体积 |
|---|---|---|---|
| `jiankujidu/telecrm-server-php` | PHP 8.1 + Apache | 后端接口 | 501 MB |
| `jiankujidu/telecrm-admin-php` | Vue3 + Nginx | 管理后台网页 | 49.9 MB |
| `jiankujidu/telecrm-server` | Java 17 + Spring Boot | 后端接口 | 376 MB |
| `jiankujidu/telecrm-admin` | Vue3 + Nginx | 管理后台网页 | 49.9 MB |

而你问的「能不能整在一起」——**能，这就是第 5 个**：

| 镜像名 | 内容 | 端口 | 体积 |
|---|---|---|---|
| **`jiankujidu/telecrm-allinone`** | PHP 后端 + 管理后台，合一 | **8080** | 约 560 MB |

### 一体版 vs 分离版，怎么选

| | 一体版 `allinone`（推荐） | 分离版 `server-php` + `admin-php` |
|---|---|---|
| 业务镜像数 | **1 个** | 2 个 |
| 占用端口 | **8080** | 8080（接口）+ 8081（后台） |
| 访问后台 | http://localhost:8080/ | http://localhost:8081 |
| 跨域问题 | 无（同源） | 需要 Nginx 转发 |
| 适合 | 单机部署、快速演示、小团队 | 前后端分开扩容、后台挂独立域名/CDN |

**绝大多数情况用一体版就够了**，这也是本部署包的默认值。想用分离版就执行：

```bash
docker compose -f docker-compose.split.yml up -d
```

### 一体化是怎么实现的

不是硬塞，而是正好三件事天然吻合：

1. 前端请求接口用的是**相对路径** `baseURL: '/api'`，同源就能通，不用改一行业务代码；
2. 后端 `.htaccess` 本来就是「文件存在就直出，不存在交给 `index.php`」；
3. Vue 打包产物（`index.html` + `assets/`）和 PHP 入口（`index.php`）**文件名不冲突**，可以放同一个目录。

所以合并后只需在 Apache 里分三条路由：

| 请求 | 去向 |
|---|---|
| 真实存在的文件/目录（后台 `index.html`、`assets/*`、`uploads/*` 录音） | 直接返回 |
| `/api/*` | 交给 `index.php`（PHP 接口） |
| 其它路径（`/customer`、`/report` 等后台前端路由） | 回落 `index.html`（SPA 深链接） |

> 有个坑我踩过并修了：Apache 的 `DirectoryIndex` 默认 `index.php` 优先，导致打开 `/` 看到的是接口 JSON 而不是后台页面。
> 已在镜像里强制 `DirectoryIndex index.html index.php`，现在 `/` 正确返回后台页面。

> ⚠️ **不能混搭技术栈**：`admin-php` 里的代理规则指向 `server:80`（PHP），Java 版指向 `server:8080`。
> 认准后缀成对：`-php` 配 `-php`，无后缀配无后缀。一体版是 PHP 栈。

## 二、三种部署方式，选一个

| 方式 | 适合场景 | 要装 Docker 吗 | 耗时 | 推荐度 |
|---|---|---|---|---|
| **A. Docker 一键部署** | 快速看效果、放服务器上跑 | 要 | 约 5 分钟 | ⭐⭐⭐ 首选 |
| **B. phpStudy 本地跑** | 你在本机改 PHP 代码 | 不要 | 约 15 分钟 | ⭐⭐ 开发用 |
| **C. 从源码自己编译镜像** | 改了代码还要用容器跑 | 要 | 15–30 分钟 | ⭐ 进阶 |

下面重点讲 **A**，B 和 C 各给关键步骤。

## 三、方式 A：Docker 一键部署（推荐）

### 第 1 步：装 Docker

- Windows / Mac：装 **Docker Desktop** → https://www.docker.com/products/docker-desktop/
- 装完重启一次，任务栏出现鲸鱼图标、命令行能跑 `docker --version` 就成了。
- Windows 家庭版会要求开 WSL2，安装向导会带着你做，一路默认即可。

### 第 2 步：解压部署包，双击脚本

把 `电销CRM-Docker部署包.zip` 解压到**任意目录**（路径别带中文和空格，例如 `D:\telecrm`），里面应该有：

```
docker-compose.yml     ← 编排文件（定义了 3 个容器）
一键部署.bat           ← Windows 双击这个
一键部署.sh            ← Linux / Mac
停止.bat
sql/                   ← 初始化 SQL（建表 + 账号 + 演示数据）
  01_schema.sql
  02_init_data.sql
  03_demo_data.sql
部署教程.md
```

**Windows**：双击 `一键部署.bat`，它会自己拉镜像 → 启动 → 等数据库初始化 → 自检 → 打开浏览器。

**Linux / Mac**：

```bash
cd docker-deploy
chmod +x 一键部署.sh
./一键部署.sh
```

**或者手动敲命令**（和脚本等价，方便你看清每一步）：

```bash
cd docker-deploy
docker compose pull      # 拉镜像，首次 2-5 分钟
docker compose up -d     # 后台启动
```

### 第 3 步：等它起来

MySQL 首次启动要执行三个 SQL 建表灌数据，**大约 40 秒**。期间后台打开会报 502，正常的，等一会儿刷新。

### 第 4 步：打开后台登录

浏览器访问 **http://localhost:8080/**

```
账号：13800000001
密码：123456
```

这个账号是**团队主（owner）**，权限最高。

### 端口一览表

| 端口 | 是什么 | 访问地址 |
|---|---|---|
| 8080 | **管理后台网页 + 后端 API**（同一个容器） | 后台 http://localhost:8080/ ，接口 http://localhost:8080/api |
| 3306 | MySQL 数据库 | 本机用 Navicat 可连 |

一体版只占 **8080** 一个业务端口，没有 8081。

### 验证是否真的跑起来了

```bash
# 1. 三个容器都应该是 Up
docker compose ps

# 2. 接口自检（返回 JSON 且 code 为 0 就是通的）
curl http://localhost:8080/api/report/overview
```

Windows 没有 curl 就用浏览器直接开 http://localhost:8080/api/report/overview ，看到 JSON 即可。

## 四、让手机 App 连上电脑上的服务

App 装好是免登录的，但它要能访问到后端才有数据。

1. **查电脑局域网 IP**：电脑 cmd 里执行 `ipconfig`，找"IPv4 地址"，例如 `192.168.1.23`。
   （别用 `127.0.0.1` 也别用 `10.0.2.2`，那是模拟器专用地址）
2. **手机装 APK**：`电销CRM-免登录版-v1.0.0.apk`。
3. **App 里填地址**：我的 → 服务器地址 → 输入 `http://192.168.1.23:8080/api` → 保存。
4. **确认同一 WiFi**：手机和电脑必须在同一个局域网。
5. **放行防火墙**（打不开就看这步）。管理员身份运行 cmd：

```cmd
netsh advfirewall firewall add rule name="电销CRM 8080" dir=in action=allow protocol=TCP localport=8080
```

> 如果你愿意，把你的局域网 IP 告诉我，我可以直接把它烧进 APK 当默认值，装完连这一步都省了。

## 五、方式 B：phpStudy 本地跑（不用 Docker）

适合你要改 PHP 代码的情况。

1. 把 `电销CRM-PHP后端-phpStudy专用.zip` 解压到 `E:\phpstudy_pro\WWW\telecrm\`。
2. phpStudy 建数据库 `tele_crm`，依次导入 `sql/01_schema.sql` → `02_init_data.sql` → `03_demo_data.sql`。
3. 改 `server-php/config.local.php`（没有就新建）：

```php
<?php
return [
    'db_host' => '127.0.0.1',
    'db_port' => 3306,
    'db_name' => 'tele_crm',
    'db_user' => 'root',
    'db_pass' => '',          // phpStudy 默认 root 空密码
    'jwt_secret' => 'telecrm-secret-change-me',
];
```

4. nginx 站点根目录指向 `server-php/`，开启 rewrite（仓库里已带 `nginx.conf`）。
5. 访问 http://localhost/telecrm/api/report/overview 看是否返回 JSON。

后台（Vue3）本地跑：

```bash
cd admin
npm install
npm run dev      # 默认 http://localhost:5173
```

> 注意：PHP 7.3 环境**不要**用箭头函数 `fn=>`、`match`、`str_contains` 这些新语法，现有代码已经全部规避，你改的时候也要避开。

## 六、方式 C：从源码编译镜像

想改代码再用容器跑，就用仓库根目录的 compose（会本地构建）：

```bash
# PHP 版（推荐）
docker compose -f docker-compose.php.yml up -d --build

# Java 版（要 Maven 编译，慢）
docker compose up -d --build
```

改完代码重新构建：

```bash
docker compose -f docker-compose.php.yml build server
docker compose -f docker-compose.php.yml up -d
```

## 七、常见问题（照着排查）

| 现象 | 原因 | 解决 |
|---|---|---|
| `Bind for 0.0.0.0:3306 failed: port is already allocated` | 本机 3306 被占用（phpStudy 的 MySQL 最常见） | 编辑 `docker-compose.yml`，把 `"3306:3306"` 改成 `"3307:3306"` |
| 8080 端口被占 | 其他程序占了 | 改左边的宿主端口，如 `"9080:80"`（分离版还要改 8081） |
| 后台打开 502 / 白屏 | MySQL 还在初始化 | 等 40 秒再刷新；`docker compose logs mysql` 看进度 |
| 后台能开但列表全空 | 演示数据没导入 | `docker compose down -v` 删库重来（见下条） |
| `pull access denied` | 镜像是私有的 | 本教程用的镜像已公开；若你自己重建过，先 `docker login` |
| 拉镜像特别慢 | 国外源 | 配镜像加速器：Docker Desktop → Settings → Docker Engine → 加 `"registry-mirrors": ["https://docker.m.daocloud.io"]` |
| App 一直转圈 / 报网络错 | 地址不对或防火墙 | App 里地址必须是 `http://电脑局域网IP:8080/api`；放行 8080 端口 |
| 后台登录提示账号密码错误 | 数据库没初始化 | `docker compose logs mysql \| findstr ERROR` 看 SQL 报错 |
| 后台/App 里中文全是 `é™ˆèŠ³` 这种乱码 | 旧版 SQL 导入时客户端字符集是 latin1 | **本部署包已修复**（每个 SQL 首行加了 `SET NAMES utf8mb4;`）。若你自己导入 SQL 出现乱码，在文件最前面加一行 `SET NAMES utf8mb4;` 再重新导入，并执行 `docker compose down -v` 清库重来 |

### 彻底重来（清空所有数据）

```bash
docker compose down -v      # -v 会连数据卷一起删
docker compose up -d        # 重新初始化，演示数据会回来
```

### 只重启不停数据

```bash
docker compose restart
```

### 看日志

```bash
docker compose logs -f server     # 后端
docker compose logs -f mysql      # 数据库
docker compose logs -f admin      # 后台
```

## 九、安全提醒

部署包里的数据库密码、JWT 密钥都是**演示默认值**，正式上线前一定要改：

1. 编辑 `docker-compose.yml`，把 `MYSQL_ROOT_PASSWORD`、`MYSQL_PASSWORD` 换成强密码；
2. 同步改 `server` 服务里的 `DB_PASS`，保持一致；
3. 后端 JWT 密钥在 `server-php/config.php` 的 `jwt_secret`（容器化时用环境变量 `JWT_SECRET` 覆盖）；
4. 别把 3306 端口暴露到公网。

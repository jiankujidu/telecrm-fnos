# 电销CRM —— 问题诊断与改进设计方案

> **v1.2.0 已落地「云端自动外呼」**（电脑端下发任务 → 手机端自动按顺序拨号）。
> **v1.1.0 已落地本文 P0 的大部分内容**（画像表、客户增删改、备份恢复、拨号修复），
> 下文保留完整设计用于后续迭代。

## 〇之二、v1.2.0 已实现：云端自动外呼

| 需求 | 实现 |
|---|---|
| 电脑点拨打 → 手机自动拨 | 后端 `dial_push_task` / `dial_push_item` 两表；手机端 `/dial-push/next` 轮询取号 → 自动拨出 → `/report` 上报 |
| 从列表里选「从哪里开始」 | 电脑端建任务时**可搜索客户**指定 `startCustomerId`，从该条起按顺序往后 |
| 设置多少秒自动下一个 | `interval_seconds`（0~600），由**服务端**按 `last_dialed_at` 计时；手机端只显示倒计时 |
| 按顺序拨 | 明细按 `seq` 排序，原子领取 `UPDATE ... WHERE id=(SELECT id FROM (... ORDER BY seq LIMIT 1) x)`，多手机不重复 |
| 随时暂停 / 跳过 / 结束 | 电脑端 `control`：start / pause / resume / stop / cancel；`skip` 跳过当前条 |
| 结果留痕 | 每条上报同步镜像写入 `call_record`（前缀【自动外呼】），报表照常统计 |

**架构取舍**：用**手机轮询拉（pull）**而不是服务端推送（push/FCM）。
理由：① 不需要 FCM/厂商推送通道，局域网自建服务器也能用；② 手机每轮都问，
电脑端改顺序/间隔/暂停后 ≤2 秒即生效；③ 手机退后台、断线、换机都不会丢序，
未完成的 `dialing` 条目重新回到 `pending`。

## 一、本次已修复的问题

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | **APK 读不出数据** | 默认地址写死 `http://10.0.2.2:8080/api`。`10.0.2.2` 是安卓模拟器访问宿主机的专用地址，真机根本不存在；且端口 8080 与飞牛实际部署端口 18080 不一致 | 默认值改为局域网可用格式 `http://192.168.1.100:18080/api`，登录页强制先填地址 |
| 2 | **登录页没有填 IP 的地方** | 服务器地址只藏在「我的 → 服务器地址」，且要先能进 App 才能改 | 登录页新增「服务器地址」输入框 + **测试连接**按钮，登录时自动保存 |
| 3 | **只有导入没有导出** | 后端只有 `/api/file/upload` | 新增 `ExportController`：`/api/export/customers`、`/api/export/call-records`，Apache POI 生成 .xlsx；前端客户页、话单页各加「导出 Excel」按钮 |
| 4 | **离线态没有提示** | 免登录模式下静默进入离线态，用户不知道为什么没数据 | 首页顶部增加橙色提示条「未连接服务器，当前为离线体验」+「去设置」直达登录页 |

## 二、现状评估：已经有什么

**后端（Spring Boot 3 + MyBatis-Plus）**：12 个控制器，覆盖客户、通话记录、任务、跟进、订单、套餐、激活码、公海、团队、报表、鉴权；逻辑删除、雪花 ID、统一响应封装、JWT 鉴权、自动建表 + 演示数据。

**前端（Vue3 + Element Plus）**：10 个业务模块，登录、客户、话单、订单、套餐、激活码、任务、团队、报表。

**移动端（Flutter）**：拨号、录音、悬浮窗连拨、未接重拨、跟进、客户详情、录音自动上传、免登录。

**部署**：单镜像 `jiankujidu/telecrm:1.0.1`（x86 + arm64 双架构），飞牛 .fpk 应用包（x86/ARM/通用），端口 18080。

整体骨架完整、能跑通业务闭环，缺的是**容错、数据出入口的完整性和运营级能力**。

## 三、专业改进设计（按优先级）

### P0 — 影响可用性与数据安全，建议 v1.1 做完

**1. 服务器地址配置体验（移动端）**
- 扫码配置：后台生成一个含服务器地址的二维码，App 扫码即填，杜绝手输 IP 出错。
- 局域网自动发现：App 启动时 UDP 广播探测，服务器回应自身地址，列表里选一下即可。
- 首页常驻连接状态灯（绿=已连接 / 灰=离线），点击可快速改地址。

**2. 导入做成完整闭环**
- 提供**标准模板下载**（客户模板 / 话单模板），避免列错位。
- 导入后返回**校验报告**：成功 N 条、失败 M 条，失败原因精确到行号（手机号为空、号码重复、超长等）。
- **字段映射**：首次导入让用户把 Excel 列映射到系统字段，并记忆该映射。
- **去重策略**可选：跳过 / 覆盖 / 保留最新（按手机号判重）。

**3. 导出增强**
- 支持**按当前筛选条件导出**（现在是 scope + 关键词，应扩展到时间范围、状态、标签、归属人）。
- 支持**自定义列**（勾选要导出的字段）。
- 大数据量（>2 万行）走**异步导出**：提交任务 → 后台生成 → 「下载中心」里取文件，避免请求超时。
- 增加**CSV 导出**选项（比 xlsx 更快、更易被第三方系统读取）。

**4. 数据备份与恢复**
- 一键**全量备份**（表结构 + 数据，JSON 或 SQL），可下载、可回传恢复。
- 定时备份到数据目录（每日 1 份，保留 7 天），飞牛用户可在文件管理里直接看到。

### P1 — 运营级能力，建议 v1.2

**5. 权限与角色**
- 当前只有「我的 / 团队」两档，缺角色模型。建议：`坐席 / 主管 / 管理员` 三级。
- 主管可看团队所有数据、可分配；管理员额外管套餐、激活码、成员。
- 数据权限下沉到接口层，前端按钮按角色显隐。

**6. 审计与操作日志**
- 记录「谁在什么时间改了哪个客户的什么字段」，客户详情页可看变更时间线。
- 敏感操作（删除、分配、导出）单独记日志，便于追责。

**7. 报表与统计**
- 当前报表是实时聚合，数据量上来会慢。建议做**日/周预聚合表**，报表读预聚合结果。
- 增加：坐席排行榜、时段接通率热力图、客户转化漏斗、录音质检抽检。

**8. 录音与存储**
- 录音目前存本地磁盘（`/app/uploads`）。建议抽象一层存储接口，可选本地 / 阿里云 OSS（依赖已引入）。
- 录音上传失败要有**重试队列**，App 断网时缓存，恢复后自动补传。

### P2 — 体验与工程化，建议 v2.0

**9. 后台首页仪表盘**
- 现在登录后直接进客户列表，缺总览。建议首页：今日拨打量、接通率、新增客户、待跟进数 + 7 日趋势图 + 坐席排行。

**10. 移动端离线可用**
- 离线时展示**已缓存的客户与话单**（上次同步的数据），而不是空白。
- 离线拨打记录先落本地，联网后批量补传。

**11. 部署与运维**
- 镜像加 `HEALTHCHECK` 与资源限制（memory/cpu），飞牛里状态更准。
- 提供**版本升级路径**：`.fpk` 升级时保留数据目录（现已支持），并在升级前自动做一次数据库备份。
- 反向代理 + HTTPS：建议飞牛上用域名 + 证书访问，App 侧填 https 地址。

**12. 接口与工程化**
- 增加接口限流（防刷）、参数校验统一返回。
- 补 Swagger 文档（已引入 springdoc）并按角色分组。
- 后端补单元测试与集成测试，CI 跑通再打包。
